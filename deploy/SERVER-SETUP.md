# Prizrak — второй сервер и звонки между серверами

Этот архив (`prizrak-server-<версия>.zip`) — только серверная часть: homeserver +
relay для звонков. Десктоп-клиента, PHP-банка и web-сайта здесь нет.

## 0. Требования
- Node.js 18+ на машине сервера.
- Открытые (в пределах вашей сети) порты: **порт homeserver'а** (по умолчанию 8801)
  и **порт relay** (по умолчанию 8810).

## 1. Установка
```bash
unzip prizrak-server-<версия>.zip && cd prizrak-server-<версия>
npm install            # поставит зависимости (@noble/*, ws) из package.json
```

## 2. Запуск одного сервера
```bash
# домен может быть любым именем — важно лишь, чтобы оба сервера и клиенты
# одинаково его РЕЗОЛВИЛИ (см. раздел 4 про resolver для локального теста).
./deploy/prizrak-deploy.sh init --domain srv2.local --admin root --registration on \
    --relay-url stealth://192.168.1.50:8810      # ← IP этой машины, видимый другим!
./deploy/prizrak-deploy.sh create-admin --password 'СильныйПароль'
./deploy/prizrak-deploy.sh start                 # окно оставить открытым
```
Relay поднимается ВНУТРИ homeserver'а автоматически, раз задан `--relay-url`
(порт берётся из него). Отдельно `relay` запускать не нужно.

## 3. КЛЮЧЕВОЕ про звонки между разными серверами
Медиа звонка идёт через relay **звонящего**: offer несёт `relayUrl` вызывающей
стороны, и ОБА собеседника коннектятся именно к нему. Значит:

- `relayUrl` каждого сервера должен указывать на **адрес, достижимый со второй
  машины** — НЕ `127.0.0.1`, а реальный IP/домен (напр. `stealth://192.168.1.50:8810`).
- Порт relay (8810) должен быть открыт между машинами.
- Звонок srv1↔srv2 работает в обе стороны: кто звонит — через того relay и идёт медиа.

Проверка в клиенте: в панели звонка счётчик `↑отпр ↧сырые ↓расшифр 🎞кадры 🔊аудио`.
Если `↧` растёт — пакеты от собеседника доходят (relay достижим). Если `↧≈0` —
relay звонящего недостижим со второй машины (проверьте IP в `relayUrl` и порт).

## 4. Федерация: чтобы серверы видели друг друга
Для доставки сообщений между серверами каждый сервер должен резолвить домен
другого в его base URL. В проде это `https://<домен>` (реальный DNS+TLS). Для
локального теста без DNS пропишите `resolver` в конфиге КАЖДОГО сервера:

`prizrak.config.json` на srv1 (домен srv1.local, порт 8801):
```json
{
  "domain": "srv1.local",
  "port": 8801,
  "relayUrl": "stealth://192.168.1.40:8810",
  "registrationEnabled": true,
  "resolver": {
    "srv1.local": "http://192.168.1.40:8801",
    "srv2.local": "http://192.168.1.50:8801"
  }
}
```
На srv2 — зеркально (свой домен/порт/IP, тот же список resolver). Тогда:
`alice:srv1.local` пишет `bob:srv2.local` → srv1 по resolver находит
`http://192.168.1.50:8801` и передаёт конверт на srv2 (сервер видит только шифртекст).

Альтернатива для локали — прописать домены в `/etc/hosts` обеих машин и
пользоваться `https://`/reverse-proxy; но resolver проще для теста.

## 5. Клиенты
В десктоп-клиенте (отдельный архив `prizrak-<версия>.zip`) при входе указывают
адрес своего сервера (напр. `http://192.168.1.40:8801`) и регистрируются как
`имя:srv1.local`. Оба клиента ОБНОВИТЕ до той же версии, что и серверы — фрейминг
звонков должен совпадать во всех трёх компонентах (оба клиента + relay).
