# Prizrak — узел-тайник (dead-drop relay)

Промежуточное **zero-knowledge** хранилище для сети тайников Prizrak. Помогает доставлять
зашифрованные конверты между серверами призраков, когда прямой путь домен1→домен2 перерезан
ТСПУ, но оба видят этот узел. Узел **никогда не может прочитать** содержимое — хранит и отдаёт
только шифртекст, пока получатель его не заберёт.

Полный дизайн и дорожная карта: `claude/Prizrak-deaddrop-relay-network.md` (Фаза 1 — этот пакет).

## Запуск
```bash
# headless (сервер):
node src/node.js
# или с UI (Electron):
npm i && npm run start:electron
```

## Конфиг (ENV)
| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DD_PORT` | 8820 | порт HTTP |
| `DD_HOST` | 0.0.0.0 | интерфейс |
| `DD_DATA` | `~/.prizrak-deaddrop` | каталог хранилища + ключ узла |
| `DD_MAX_BYTES` | 2 ГБ | общий лимит диска |
| `DD_MAILBOX_BYTES` | 64 МБ | лимит на один ящик |
| `DD_BLOB_BYTES` | 16 МБ | лимит на один блоб |
| `DD_ACK_TTL_MS` | 7 дней | сколько помнить ACK (для реконсиляции) |
| `DD_PUBLIC` | `http://127.0.0.1:PORT` | публичный URL узла (виден другим в реестре) |
| `DD_SEEDS` | — | сид-узлы через запятую (для входа в сеть) |
| `DD_GOSSIP_MS` | 30000 | период госсипа реестра |

Идентичность узла (`relayId` = Ed25519 pubkey) создаётся при первом старте в `DD_DATA/identity.json`.
Приватный ключ **никогда** не покидает узел.

## Эндпоинты (Фаза 1)
- `PUT /dd/put` — тело = ciphertext; заголовки `X-DD-MsgId`, `X-DD-Mailbox`, `X-DD-Epoch`, `X-DD-Expiry`.
  Узел проверяет `msgId == BLAKE3(ct)` и квоты. Если msgId уже доставлен (есть ACK) → `stale`.
- `POST /dd/poll` `{mailbox, since}` → `{items:[{msgId,size,at}]}`.
- `GET /dd/get/{msgId}` → ciphertext (или 404).
- `POST /dd/ack` `{msgId, pub, sig}` — подпись получателя над msgId; узел проверяет подпись И что
  `mailbox == HKDF(pub, epoch)` (только владелец ящика вправе удалить) → удаляет блоб, помнит ACK.
- `POST /dd/have` `{msgIds}` → `{acked, present}` — что доставлено / что ещё лежит.
- `GET /dd/health` → `{nodeId, version, uptimeMs, blobs, bytes, mailboxes, acks, peers}`.
- `GET /status` — локальная статус-страница оператора (в браузере, только с localhost).
- Прочее → страница-обманка `It works` (маскировка от зондирования).

## Реестр узлов (Фаза 2)
Узлы находят друг друга без центра — подписанным госсипом:
- `POST /registry/announce` `{records:[…]}` — принять чужие подписанные записи.
- `GET /registry/list` → `{records}` — отдать известные записи.
- Запись `{relayId, endpoints, addedAt, sig}` подписана ключом самого узла (`relayId`); подделка
  (подмена endpoint) не проходит проверку.
- Периодически узел анонсирует себя сидам/известным узлам и подтягивает их списки.
- **Детерминированное размещение** (`src/placement.js`, HRW≈CRUSH) считается по равномерному весу
  над членством реестра → ВСЕ узлы получают ОДИН набор реплик для msgId (получатель знает, где
  поллить). Локальный `score` (аптайм) — для приоритизации отправителем, не влияет на набор.

Запуск сети из двух узлов локально:
```bash
DD_PORT=8820 node src/node.js                                   # узел A
DD_PORT=8821 DD_DATA=~/.dd-b DD_PUBLIC=http://127.0.0.1:8821 \
  DD_SEEDS=http://127.0.0.1:8820 node src/node.js               # узел B (войдёт через A)
```

## Безопасность
- **Контент E2E** (шифрует отправитель) — узел видит только шифртекст.
- **Слепые ящики**: адрес = `HKDF(recipientPub, epoch)`; узел не знает домен получателя.
- **ACK = подпись получателя** — единственный, кто может авторизовать удаление блоба.
- Контент-адресация (`msgId=BLAKE3(ct)`) — защита целостности и дедуп.
- Квоты + TTL — защита волонтёрского диска.

## Самоисцеление реплик (Фазы 4–5, модель Ceph) — `src/healer.js`
Для каждого блоба узел вычисляет детерминированный набор реплик `placement(msgId, RF)`.
- **primary** = первый живой узел набора — он ОДИН доливает недостающие копии (`/dd/put`) до RF
  (аналог Ceph backfill: «с живых реплик долить на ещё один живой»), чтобы не делали все разом.
- **ACK-протухание:** если сосед-реплика уже доставил (вернул проверяемый ACK через `/dd/have`),
  узел применяет ACK и удаляет свою копию.
- **Rebalance:** если копия стала лишней (размещение сместилось, а живых правильных копий хватает)
  — узел её снимает. Так вернувшийся из офлайна узел сам подчищает устаревшее/лишнее.
- Конфиг: `DD_RF` (по умолч. 4), `DD_HEAL_MS` (период, 20с).
